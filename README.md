# 帳票OCRツール（Chohyo）

手書きの定型帳票をスキャンした PDF を読み取り、**1枚＝1行** の Excel（.xlsx）と CSV に変換するデスクトップツール。画像の中の文字を読み取る処理（OCR）には、Google が提供するクラウドの画像認識サービス Google Cloud Vision API を使う。

設計の前提は「**空欄を出すコストより、誤った値を出すコストの方が大きい**」。自信を持って読めなかったセルには値を出さず **〓** を置き、行頭の「要確認セル数」で人が直す箇所を絞り込む。読めない箇所を推測で埋めない（詳細: [要件定義書](docs/design/chouhyo-ocr/01_requirements.md)）。

- 出力の列構成は、テンプレート（帳票のどこに何が書かれているかの定義）から自動で決まる。現行の chouhyo-v1 は 220列＝管理6＋本人14＋家族欄60＋明細140（本人14には郵便番号1/2 を含む）。目で確かめて提出に使うのは .xlsx、.csv は他のシステムへ取り込む用。**エディタで欄を足せば列は増え、欄を出力から外したり並べ替えたりすれば列の数と順序も変わる**。.csv を取り込むシステムがある場合は、列構成の変更を先方と合わせてから保存する
- 〓には2種類ある。欄全体が読めなかった場合はセルの値がちょうど `〓`（黄背景）、一部の文字だけ信頼度が足りない場合はその文字だけが `〓` になる（例: `旭〓市`・橙背景）。後者は既定では出ない——`unclear_char_level` を ON にしたときだけ有効になる（下記）。要確認セル数（Excel の COUNTIF＝条件に合うセルの数を数える関数で計算している）は、既定では `〓` の完全一致だけを数える。ON にすると一部〓のセルも含めて数える。直すたびに自動で減る
- 参照先（郵便番号を専用欄でなく住所欄の書き出しに書いた場合に読み取る救済枠など）から値を採ったセルには薄い青の背景色が付く。**この由来色は .xlsx だけの表示で .csv には出ない**（.csv には色を付けられず、由来を示す列も増やせないため）。同じセルが〓にもなった場合は〓の色が優先表示される
- 中断・再実行しても処理済みの紙は再送信しない（API 課金を無駄にしない）

## オペレーター向け（読み取る人）

1. インストーラ `chouhyo-ocr_x64-setup.exe` を実行する。このアプリにはコード署名（開発元を証明する電子署名）が付いていないので、SmartScreen（Windows が知らないアプリの起動時に出す警告画面）が表示される。「詳細情報」→「実行」で進む
2. アプリを起動し、初回のみ「認証キーを選択」で管理者から受け取った JSON キーを取り込む。取り込みに成功すると暗号化して保存され、受け取った元のファイルはアプリが自動で削除する（削除できなかったときは画面にその旨が出るので、手で削除する。鍵が平文のまま残らないようにするため）
3. **スキャンのファイル名は連番にする**（例: `scan_0001.pdf`）。ファイル名は Excel の「入力ファイル名」列やログにそのまま出るため、氏名などを含めない
4. 画面の手順どおり: **1** 帳票 PDF のフォルダを選択 → **2** Excel の保存先を確認 → **3** 読み取りを開始
5. 完了したら「出力フォルダを開く」→ Excel の「要確認セル数」を大きい順に並べ替え、色つきの 〓 を紙の原本と見比べて直す。合計が 0 になったら完成

読み取り開始の前に「**このテンプレートは N 欄を出力しません**」と出ることがある。これは管理者がその欄をわざと出力から外している合図で、故障ではない（紙は今までどおり読み取る）。出るはずの列が Excel に無いときは、この表示と管理者に確認する。

途中で終了しても問題ない（次回は未処理分から再開する）。インターネット接続が必要。

## 管理者向け

- **テンプレート編集** タブで、帳票のどこを読み取るか（枠）を決める。流れは「帳票を開く → 枠の候補が自動で出る → 保存済みのテンプレートを使うか、候補から作るかを選ぶ」。
  - **帳票を開く**: 画像か PDF を開くと、罫線から枠の候補をまとめて作り、破線で表示する。罫線の多い紙ほど時間がかかる（そのあいだ枠を扱うツールは押せない。拡大とスクロールはできる）
  - **どちらか選ぶ**: 画面の上に「テンプレートを選ぶ」が出る。この紙に合いそうな保存済みテンプレートが並ぶので、使うものの **「このテンプレートを使う」** を押す。出荷テンプレートも同じ並びに「（出荷）」付きで出る。候補から作るなら **「候補から新しく作る」**
  - **候補から作る**: 右の「枠候補」タブでチェックして採用し、欄に名前を付けて保存する（詳しい手順は下の「新しい紙のテンプレートを作る」）。候補は升（ます＝表のセル）が基本で、罫線で閉じた四角形はすべて升の候補として出る。等間隔に同じ列構成で並んだ行は「この並びは表にまとめられます」という提案として一覧の上に出るので、**「表にまとめる」**（表として採用）、**「升のまま採用」**（1升ずつ欄として採用）、**「この提案を消す」**から選ぶ。高さの違う先頭の1行は表に含めず升の候補のまま残し、提案に**「見出し行は含めていません」**と出る。行ごとに列の並びが違う部分（小計・合計のように升が結合されている所）は表にまとめず、升の候補のまま残る
  - **前回のテンプレートは記憶される**: 適用すると画面の上が1行の帯になり「適用中のテンプレート: 〈名前〉」と出る。次に帳票を開いたときは、そのテンプレートが自動で適用される（帯に「（前回と同じものを自動で適用しました）」と付く）。候補からやり直すときは帯の「候補から新しく作る」を押す。自動で作るのを止めたいときは `auto_detect_frames_on_open` を `false` にする（下の設定の項）
  - タブを開いた時点では前回選んだテンプレート（初めは出荷テンプレート）が読み込まれていて、欄一覧・出力列タブはすぐ使える。ただし枠が記入欄に重なって見えるのは、帳票を開いて位置合わせが済んでから。画像を開くまでキャンバス（帳票の画像を表示して枠を描く作業スペース）は白い下地と案内だけ。枠を扱うツールボタンと側パネルの追加系ボタンは無効になり、ドラッグや矢印キーでの移動もできない（欄の選択・名前変更・出力トグル・削除は欄一覧から行える）
  - ツールバーの **「くり返し行（家族・明細）」** で表の外枠を描くと、罫線から行と列を自動で見つける（見つけられなければ等分割に切り替わる）。紙の一部だけを対象にしたいときに使う
  - 保存すると読み取り処理の本体（コア）が中身を検査し、列数・金額列数を表示する。列数が多い少ないで保存を断ることはない。断るのは、列名の重複・枠の重なり・面からのはみ出しなど、出力が壊れる場合だけ
- **利用者テンプレートの置き場所**: 編集画面で「利用者テンプレートとして保存」したものは `%APPDATA%\com.holodev.chouhyo-ocr\templates_user\` に入る。インストール先の外にあるので、アプリを更新しても消えず、配布物にも混ざらない。中間データを消すコマンド `purge` でも消えない。別の PC へ持っていくときは「書き出し」「取り込み」を使う。読み取りに使うテンプレートは実行タブの上部で選ぶ（通常は出荷テンプレートのまま）
- **様式が合わない紙**（テンプレートを適用しているときの話）: 帳票を開いたとき、テンプレートの罫線と一致しない紙（別の様式）は枠を表示せず、黄色の帯で案内する。**枠の候補を出している状態（テンプレートをまだ適用していない状態）では、この案内は出ない**——比べる相手のテンプレートが無いため。用紙のサイズや向きがテンプレートと違う紙は、黄色ではなく赤い案内になる（どちらにも「この紙用に新しいテンプレートを作る」ボタンが出る）。罫線が薄くて判定できない紙は、従来どおり枠を重ねて表示する（読み取り時に自動補正される）。判定を無視して枠を出したいときは、帯の「それでもこのテンプレートで開く」を押す。読み取りでは、様式の合わない紙は Vision へ送らず `様式不一致` の全〓行になる。実行画面には「送信前・課金なし」の件数と理由が出る
- **欄を出力から外す**: 右パネルの「出力する」チェックを外すと、その欄は .xlsx にも .csv にも列として出なくなる。枠・座標・項目種別・読み取りは残るので、**削除と違って後から戻せる**——戻した後は、コマンドラインで `remap` を実行すると値が復帰する（画像を送り直さないので課金なし。GUI にはこの操作が無い。打ち方は下の「CLI」の節）。外した欄は画面上で斜線と ⊘ が付き、「出力列」タブに一覧と件数が出る。JSON では `output: false` を書いたときだけ外れる（省略＝出力する）。全欄を外すと保存が拒否される（列が1つもない .xlsx は壊れるため）
- **表の升（ます）を1つだけ出力から外す**: 表は升ごとにも指定できる。Excel では表の升が1つずつ列になる（`明細_01_品名` … `明細_10_備考`）。列ごとに外すと `明細_01_備考` から `明細_10_備考` までの10列がまとめて消え、升ごとに外すと `明細_03_備考` の1列だけが消える。指定するには、キャンバスで表を選んでから升をクリックし、右パネルの「選択中の升」で「出力する」を切り替える。**列ごと出力しないにした列では、升の指定は効かない**（列の指定が優先）。指定そのものは列を戻すまで画面に残り、戻すとまた効く。ただし列を外したまま保存すると、その列の升の指定は保存されない。出力しない升は斜線で示し、⊘ は縦に続く出力しない升のまとまりに1つだけ付く。「出力列」タブでは表が行×列のグリッドになり、列の見出しを押すとその列をまとめて切り替えられる。JSON では表の `output_disabled_cells` に外した升だけを書く（省略＝出力する）。欄と同じく読み取りは残るので、戻して `remap` を実行すれば値が復帰する（再送信しないので課金なし）。保存の前に出る確認は「出力列が 220 → 205 列に減ります。」と、管理6列を含めた列数で出る。保存した後のサマリは「214列 → 199列」と、要確認セル数が数える範囲（管理6列を除いた列）で出る——数える範囲が違うので、2つの数字は揃わない
- **列を並べ替える**: 同じ面の欄どうしは「出力列」タブの `↑` `↓` ボタンで、表の内部列は表を「開く」→ `↑` `↓` で並べ替える。表は面のいちばん後ろに固定されている（列が「単発欄 → 表」の順に並ぶため）。管理6列も先頭固定で動かせない。**並べ替えを含む保存では枠の自動調整（重なった枠を保存時に自動で切り詰める処理）が働かない**——重なりが残っていると保存が中止されるので、先に重なりを解消してから並べ替える。**並べ替えは列の単位だけで、升ごとの並べ替えは無い**
- **.csv を取り込むシステムがある場合**: 列が減る保存では確認ダイアログが出る（列順だけの変更なら確認は出ず、保存後のサマリに「列順を変更」と報告される）。どちらの場合も、先方と列構成を合わせてから保存する。列が減れば、要確認セル数が数える範囲も同時に縮む（保存サマリに「214列 → 211列」の形式で出る）。出力先には .xlsx / .csv と並んで `output_<日時>_columns.txt` が書き出される（1行1列名・管理6列を含む出力順そのまま・BOM 付き UTF-8＝文字化けしにくい形式で保存している）。列構成を先方に連絡するときは、このファイルを渡す
- 設定（歯車）: 〓閾値・丸印閾値・送信上限・保存先3種の6項目のみ（`config.json`）。閾値（しきい値）は「ここを境に判定を変える値」のこと。〓閾値は、読み取りの自信がどこまで低ければ〓にするか。丸印閾値は、元号などの選択肢を丸で囲む欄で、どのくらいはっきり囲まれていれば「選んだ」とみなすか
- 中間データ（`workdir/`＝読み取り結果や展開した画像を溜めておく作業フォルダ）は、記入内容がそのまま入るため**個人情報として扱う**。クラウド同期の対象外の場所に置く。削除は実行画面の「読み取ったデータを削除」から行える（コマンドで打つなら `purge --yes`。打ち方は下の「CLI」の節。消えるのは中間データだけで、出力ファイルは残る）。テンプレート編集で帳票を開くと `workdir/editor_pages/` にも展開画像（位置合わせ済みの下地を含む）が作られ、これも `purge` で消える。枠候補の一括生成で PDF を渡した場合の展開画像は `workdir/detect_frames_pages/` に分けて作られる（こちらも `purge` の対象）。**取り込み済みの認証キー（DPAPI 暗号化）は消えない**——認証キーは作業フォルダの外（`%LOCALAPPDATA%\ChouhyoOCR\cred.dpapi`）に置いてあり、`purge` が触る範囲に無い。`purge` のあとに認証キーを取り込み直す必要はない（以前の版で作業フォルダに取り込んだキーは、次に読み取ったときに自動で新しい置き場へ移る）
- **同じ名前のファイルを差し替えて読み取ると、前のファイルの読み取り結果は自動で消える。** 中身の違う紙を前と同じファイル名で入れて読み取りを始めると、そのファイルの古い読み取り結果を捨ててから読み直すので、新しい方だけが Excel に出る。古い値が「正常」の顔で残らないようにするため。中間データがひとりでに消えるのはこの1つだけで、それ以外は `purge` を打つまで残る
- **出力ファイル（`.xlsx` / `.csv` / `_columns.txt`）には読み取った記入値がそのまま並ぶ**。削除は `purge --include-output --yes`。ただし消えるのは**このツールが書いた命名に一致するファイルだけ**——`output_<日時>.xlsx` / `output_<日時>.csv` / `output_<日時>_columns.txt` と、その `.bak` `.tmp`（日時は `20260902_101530` の形式）。名前を変えたファイルや、別フォルダへコピーした分は残る。フォルダ自体も消さない（出力先をデスクトップにしていても、他のファイルを巻き添えにしない）。削除した件数と「対象外として残した件数」が画面とログに出るので、残った件数が 0 でなければ中身を確認する（数えるのは出力先の直下にあるファイルだけで、サブフォルダとその中身は削除も件数の集計もしない）。Excel で開いたままのファイルは削除できず、件数を出してエラー終了する（終了コード 1）——閉じてからやり直す
- **入力の寸法検査**: 入力画像の縦横比がテンプレートの `image_size` と 1% を超えてずれるページは「様式不一致」として扱い、Vision へ送らずに全〓の行を出す（用紙サイズ違い・向き違い・端が切れたスキャンを見つけるため）。ログ（`logs/app.log`。設定でログ出力先を変えていればそのフォルダ）の `page_scale`（`sx` / `sy`）にテンプレートに対する倍率が出るので、1.0 から離れている軸で切り分ける
- **文字単位〓（一部の文字だけを〓にする機能）は GUI の設定画面には出ない。** `config.json` を直接編集し `unclear_char_level` を `true` にする（既定 `false`）。ON にする前に、使っている Excel のバージョンで `COUNTIF` のワイルドカード検索（`"*〓*"`＝「〓を含むセル」という書き方）が要確認セル数を正しく数えるか、一度確認する——未確認のまま ON にしない。OFF のままなら要確認セル数・COUNTIF・条件付き書式は今までどおり動く（ON にしたときだけ挙動が変わる）

- **枠の自動合わせ（吸着）も GUI の設定画面には出ない。** `config.json` を直接編集し `snap_blocks` を `true` にする（既定 `false`）。ON にすると、表のかたまりごとに枠を紙の罫線へ縦方向だけ合わせ直してから読む——紙が伸び縮みして「上のかたまりは合うのに下だけ数 px ずれる」入力を拾うための機能。合わせ先を確かめられなかった面（罫線がかすれている・動かすと隣の欄と重なる）は、その面だけ 1 つも動かさずテンプレートの位置で読む（見送った件数は実行画面に出る）。**合わせた結果が正しいかどうかを機械で確かめる手段は無い**ので、ON にする前に下の `snap-diff` で ON と OFF の差を確かめ、差が 0 件か、差の出た欄を全部見て ON 側が正しいと判断できたときだけ ON にする。OFF のままなら読み取り結果は今までどおり（読み取り済みのデータもそのまま使えて、再送信は発生しない）
- **`snap-diff`（枠の自動合わせの差を数える）**: `snap_blocks` を `true` にして一度読み取った後、`snap-diff` を打つと、自動合わせの ON と OFF で値が変わる欄が何件あるかを数える。**数えるだけで、読み取り結果も出力ファイルも書き換えないし、Google へも送らない**（読み取り済みのデータを一時的な複製から読むだけ）。出す情報は件数と「どの紙のどの列か」までで、書かれていた内容は出さない。OFF のまま読み取ったデータには比べる相手が無いので、その場合は理由を出して何もしない

- **紙を開いた直後の枠候補づくりも GUI の設定画面には出ない。** 既定は ON——テンプレート編集で画像・PDF を開くと、罫線から枠の候補をまとめて作って破線で出す（下の「新しい紙のテンプレートを作る」と同じ作り方）。候補は空のテンプレートの上に出るので、一覧でチェックして採用するまで読み取り結果は変わらない。前に適用したテンプレートが記憶されているときは、候補を作らずにそれを適用する。`false` にすると、自動生成も記憶からの自動適用も止まり、以前の版と同じ動きに戻る。罫線の多い紙で開くたびに待たされるのが気になるときに使う（`config.json` を直接編集する）
- `config.json` には、このほかにアプリが自分で書く項目がある（`last_template`＝実行画面で最後に使ったテンプレート、`last_applied_template`＝テンプレート編集で最後に適用したテンプレート。どちらも名前だけで、場所（絶対パス）は保存しない）。手で書き換える必要は無い

### 新しい紙のテンプレートを作る（枠候補の一括生成）

罫線で枠が閉じている帳票なら、矩形を1つずつ引かずに枠候補をまとめて作れる。

1. **テンプレート編集** タブで対象の帳票の画像か PDF を開く。**前に適用したテンプレートが無ければ、枠候補はここで自動で作られる**ので手順2は要らない。前のテンプレートが自動で適用されたときは、上の帯の「候補から新しく作る」を押す——空のテンプレートに戻り、候補が作り直される。様式が合わないと出たときは、案内の「この紙用に新しいテンプレートを作る」から始める（このボタンも続けて候補まで作る。用紙サイズ／向きが合わない赤い案内でも同じボタンが出る）。新規作成したテンプレートは表面1面から始まる——**片面の紙は面を分けなくてよい**（表裏のある紙だけ「表裏の境界」ツールで面を分ける）
2. 候補が出ていないときや、作り直したいときは、ツールバーの **「ページ全体から枠候補を生成」** を押す（範囲を選ぶ必要はない。処理中はキャンバスの枠操作ができなくなるが、拡大とスクロールはできる）
3. 右の候補一覧で、**使う候補にチェック**を入れる。候補はキャンバス上で破線・角のマーカー・`?` 付きの番号で描かれ、確定済みの枠と見分けられる。既存の枠と重なる候補はチェックできない（そのままでは保存時の重なり検証で弾かれるため。個別の「採用」ボタンからは確認つきで採用できる）
4. **「選んだ候補を採用」** で確定枠にする。既存の枠は削られない。要らない候補は「すべて除去」で消す（確定済みの枠は消えない）
5. 採用した欄に**名前を付ける**（既定は `field_01`…）。表の列名は既定が `列1`…なので、候補パネルの「接頭辞」欄に語を入れて「採用した表の列名を接頭辞で一括変更」を押すと `語_1`…にまとめて変えられる。1つずつ直してもよい
6. **保存**する（「利用者テンプレートとして保存」または読み込んだファイルへの上書き）。保存時にコアが検証し、列名の重複・枠の重なり・面からのはみ出しがあれば拒否される

**くり返し行（表）の無い紙も保存できる。** 申込書のように単発の欄だけが並ぶ紙では、欄の枠線そのものを位置合わせの目印に使う。目印にできるのは幅も高さも 40 ピクセル（300dpi）以上ある欄なので、そういう欄が 1 つも無い面は保存できない（そのときはメッセージがどの面かと必要な大きさを示す）。目印になる欄が 2 つ以下のときは保存はできるが、罫線のかすれや記入のはみ出しで読み取りが止まりやすい旨の注意が出る。

検出はしたが候補にしなかった枠は、内訳（用紙の外枠・小さすぎる・面をまたぐ・四角形になっていない・四方が線でつながっていない）が件数で出る。思ったより候補が少ないときはここを見る。

生成をやり直したいときは Ctrl+Z で生成前に戻せる。テンプレートを読み込み直したり別の画像を開いたりすると候補は消える（前の画像の座標の枠が残らないようにするため）。

**限界**: 検出できるのは**罫線で四方が閉じた枠**だけ。下線だけの欄・手書きで引いた線・かすれて薄い線は候補に出ないことがある。候補が0件のときは理由（罫線が無い／閉じた枠になっていない／用紙の外枠だけ／線が多すぎて打ち切り）が画面に出るので、そのときは「くり返し行（家族・明細）」で外枠を描いてからの生成（範囲を指定する従来の方法）か、手で枠を引く。

### 運用の目安: 1バッチ＝1 workdir、提出したら purge

`run`（読み取りの実行。GUI の「読み取りを開始」と同じ処理）は末尾で、中間データに残っている**全ページ**を .xlsx / .csv へ書き直す。前回までの分を差分で足すことはしない——同じ中間データからは何度実行しても同一の出力になる再現性（要件 §6.2）を優先しているため。書き出しは実測 7.1ms/行（220列）なので、`purge` せずに 5,000 頁ぶん溜めると、新しく1頁だけ読み取った実行でも末尾の書き出しに約35秒かかる。

- 目安は **1バッチ＝1 workdir、提出が済んだら `purge --yes`**（出力ファイルも消すなら `--include-output`）。溜めるほど遅くなるのは処理そのものではなく最後の書き出し
- 累積が 1,000 頁を超えると、GUI の完了画面に「中間データに N ページ蓄積しています（出力の書き出しに M秒）。提出済みのバッチは下の「読み取ったデータを削除」から削除してください。」が出る。削除は実行画面の「読み取ったデータを削除」からも行える（コマンドラインの `purge --yes` でも同じ。打ち方は「CLI」の節）。N は `run` サマリの `total_done_pages`（`state='done'` の累積件数）、M は `render_seconds`（末尾の書き出しの実測秒）

## CLI（GUI と同じ処理を単体実行できる）

```
cd core
..\.venv\Scripts\python.exe -m chouhyo_ocr.cli <command>
```

| コマンド | 何をするか | API 送信 |
|---|---|---|
| `run --input <dir>` | 一括読み取り（`--replay <dir>` を付けると保存済みの応答を使い回すので課金ゼロ） | する |
| `render` | 閾値変更後などに .xlsx/.csv を作り直す | しない |
| `remap` | テンプレートの枠変更後にセル割付をやり直す（幾何変更は `run` が必要と拒否される） | しない |
| `detect-grid --image <png> --region x,y,w,h` | 罫線から表の行・列を検出（`--mode uniform --rows N --cols M` で等分割） | しない |
| `detect-frames --input <画像\|PDF>` | ページ全体の罫線から升の候補と「表にまとめられます」の提案を一括生成（範囲指定は不要。`--page N` / `--dpi N` / `--template <path>`。テンプレートを渡すと除外領域を潰し、候補に面と既存枠との重なりを付ける） | しない |
| `status` / `verify` | 進捗表示／テンプレート・Poppler（PDF を画像に変換するために同梱している外部ツール）・資格情報の点検。`verify --expect-columns N` は、出力される列数が N 列未満なら NG にする（取り込み先と列構成を合わせた後の突き合わせ用。N 以上なら OK）。環境変数 `GOOGLE_APPLICATION_CREDENTIALS` の平文の鍵で動いている場合は、資格情報チェックが `warn: true` を返し、GUI の実行画面に警告が出る（取り込むまで消えない。そのままでも実行はできるが、`import-credentials` で DPAPI＝Windows に最初から入っている暗号化の仕組みへ取り込むことを推奨） | しない |
| `import-credentials <json>` | 鍵を DPAPI 暗号化で取り込む（保存先は `%LOCALAPPDATA%\ChouhyoOCR\cred.dpapi`）。`--delete-source` を付けると、取り込みに成功した後で元の JSON をランダムなデータで3回上書きしてから削除する。付けない場合は元のファイルが平文のまま残るので、手で削除する | しない |
| `debug-images` | 読み取りの可視化画像（どの文字がどの欄に入り、なぜ〓かを1ページ1枚のPNGで表示。出力先は `workdir/debug/`＝個人情報扱い） | しない |
| `diag-overflow` | 欄からの溢れ（郵便番号などで、枠に入りきらなかった文字が右隣へはみ出した疑い）が**何件あるかを数えるだけ**の点検。読み取り済みのデータだけを見るので、何も直さないし何も書き換えない。1件ずつ「どの紙のどの欄か」と字数を出し、最後に合計を出す（書かれていた内容は出さない）。`--band-scale N` で右をどこまで見るかを変えられる（既定は欄の高さぶん） | しない |
| `snap-diff` | 枠の自動合わせ（`snap_blocks`）の ON と OFF で、読み取った値が変わる欄が**何件あるかを数えるだけ**の点検。読み取り済みのデータを一時的な複製から読むので、出力ファイルも中間データも書き換えない。件数と「どの紙のどの列か」を出し、書かれていた内容は出さない。`--page <帳票ID>` で1枚だけ、`--limit N` で一覧の上限を指定できる。OFF のまま読み取ったデータには比べる相手が無いため、理由を出して何もしない | しない |
| `purge --yes` | 中間データの削除（`--include-output` を足すと出力先の生成物も削除。命名が一致するファイルだけで、フォルダと改名・コピーした分は残る） | しない |

配布版の `chouhyo-core.exe` をコマンドラインから直接使うときは、`--template <パス>` でテンプレートの置き場所を渡す。画面で自分のテンプレート（`user:<名前>`）を選んでいた場合、その置き場所は画面から起動したときにしか分からないため、省略すると「指定してください」と出て止まる。

## セキュリティ・取り扱い注意

- **`.csv` を Excel でダブルクリックして開かない。** 先頭の 0 が落ちるうえ、`=` `+` `-` で始まる値が計算式として実行されてしまう（実機確認済み）。中身を見るときはテキストエディタで開くか、Excel の「データ」→「テキストまたは CSV から」で全列を文字列として取り込む。目視確認と提出には `.xlsx` を使う（こちらは文字列型を固定しており影響を受けない）
- 実運用の帳票データは指定端末のみで扱い、検証後に削除する（要件 §6.5）
- **開発担当者向け**: `workdir/`（読取値・展開画像）・`output/`・出力の `.xlsx`/`.csv`・鍵ファイルは `.gitignore` 済み（Git の管理対象から外してある）。リポジトリへ入れない。除外は拡張子で見るので、`customer.xlsx` のように名前を変えたものも対象に入る（以前は `output_` で始まる名前しか見ておらず、改名すると素通りした・issue #98）
- **開発担当者向け**: コミット前チェックを有効にする: `git config core.hooksPath .githooks`。`.githooks/pre-commit` が次のものを止める。
  - 帳票の成果物: `.xlsx`/`.xls`/`.xlsm`/`.csv`、併記される列名一覧（`_columns.txt`）、書き換え途中の一時ファイル（`.tmp`）
  - 帳票の画像と PDF: png/jpg/jpeg/tif/tiff/bmp/pdf
  - 中間データと鍵: `workdir/`・`*.dpapi`・`*.sqlite`/`*.sqlite3`/`*.db`・`*.pem`/`*.key`
  - `.json` 全部（認証キーは JSON で配られるため）。ただし追跡してよいと分かっているファイル——テンプレート・スキーマ・GUI の設定・検証用データ——は名指しで除いてある。新しく `.json` を追跡したいときは、中身が鍵でないことを確かめてから `.gitignore` と `.githooks/pre-commit` の両方に 1 行足す
  - 差分に**鍵の中身らしいもの**を含むファイル（名前を変えても中身で捕まえる）。見ているのは項目名ではなく中身の量で、本物の認証キーだけが持つ長さ——長い秘密鍵の値・40 桁の鍵 ID・PEM（鍵をテキストで表す形式）の本体らしい行・PEM の先頭行の直後に本体が続く書き方・Google の API キー——に反応する。認証キーを扱うソースやそのテストのように、項目名を書いているだけのファイルは止めない。改行を詰めた形・行頭を字下げした形・改行コードが Windows 形式の場合も拾う

  アプリ同梱の `gui/src-tauri/icons/`・`gui/public/` は画像ルールだけ免除で、そこに置いた `*.sqlite` や PDF は他と同じく止まる。`.gitignore` は `git add -f` とルール追加前に add された分を止められない——実際に add だけされた帳票画像6枚と Vision 応答2件が到達不能 blob として 9.9MB 残っていた（issue #44）ので、これが手元の最後の関門になる。検出パターンの正本は `.githooks/pre-commit` の `scan_content` 呼び出し——ここに逐語で書くと README 自身がフックに引っかかる（実測）
- **開発担当者向け**: GitHub 側にも同じ検査を置いてある（`.github/workflows/guard.yml`）。全ブランチへの push と Pull Request のたびに、その差分のパスと中身を見て、該当があればチェックを失敗させる。検出しても中身は表示せず、ファイル名と種別だけを出す（実行ログは公開リポジトリでは誰でも読めるため）。
  **これは見つけるための仕組みであって、止めるための仕組みではない。** チェックが走る時点でファイルはすでに GitHub にあり、公開リポジトリなのでその瞬間から誰でも取得できる。赤くなったら「防げた」ではなく「漏れた」ので、認証キーなら失効と再発行、帳票なら影響範囲の確認まで行う。
  実際に止めるのは、①手元のコミット前チェック、②GitHub の secret scanning の push protection（push そのものを拒否する。2026-09-03 時点で有効。ただし提供元が分かっている認証キーが対象で、帳票の `.xlsx`/`.csv` は対象外）、③main へ入れる前にこのチェックを必須にする設定、の 3 つ
- Vision へ送る画像は除外領域（綴じ穴・黒塗り・印字ラベル）をマスクしてから送信する

### 鍵の残余リスク（DPAPI で守れる範囲）

`import-credentials` が保存する `cred.dpapi` は `%LOCALAPPDATA%\ChouhyoOCR\` に置く（作業フォルダの外なので `purge` では消えない）。中身は Windows DPAPI（Windows に最初から入っている暗号化の仕組み）の CurrentUser スコープ（今ログインしているアカウント単位の設定）で暗号化している。ログインしている Windows アカウントに結びつけて暗号化するので、別のユーザーや別の PC からは読めない。ただし追加の合言葉は使っていないため、**同じ Windows アカウントで動くプロセスなら何でも復号できる**（別プロセスからの復号成功を確認済み・issue #52 M-13）。そのユーザーとして動くマルウェアは止められない。これ以上絞ると起動のたびにパスフレーズ入力を求めることになり、オペレーターの運用が回らない。守りは運用側で足す。

- **IAM（Google Cloud 側の権限設定）を Vision の呼び出しだけに絞る。** サービスアカウント（このツールが Google に自分を名乗るための鍵の持ち主）には Vision API の利用に必要な権限だけを付け、Storage・BigQuery・IAM 管理の権限は付けない。こうしておくと、鍵が漏れたときの被害が「勝手に OCR を実行されて課金される」で止まる。課金側の歯止めは `api_monthly_cap`（既定 900 ユニット）と GCP 側の予算アラートの二重
- **鍵を新しいものに入れ替える周期を決める。** 目安は 90 日。同じ PC 上のプロセスから復号できてしまう以上、鍵の寿命がそのまま被害の上限になる。手順は「GCP コンソールで新しい鍵を発行 → `import-credentials <json> --delete-source` で取り込む（`--delete-source` を付けると、取り込みに成功した後で元の JSON をランダムなデータで3回上書きしてから削除する） → GCP コンソールで旧鍵を削除」。オペレーター端末が複数あるなら全台を同じ日に回す
- **端末のマルウェア対策が最後の防衛線。** DPAPI は端末が乗っ取られた後を守らない
- **`workdir` を置くフォルダの ACL（誰が読み書きできるかの設定）を、使うユーザー1人だけに絞る。** 中間データには読み取った記入値がそのまま入るので、鍵と同じ扱いにする。鍵そのものが入る `%LOCALAPPDATA%\ChouhyoOCR\` は既定でそのユーザーだけの領域なので、追加の設定は要らない。次の PowerShell で、親フォルダからの継承を切り、そのユーザーのフルコントロールだけを残す（`icacls` は ACL を変える Windows のコマンド）:

```powershell
icacls C:\ChouhyoWork /inheritance:r /grant:r "${env:USERNAME}:(OI)(CI)F"
```

## API の課金と安全装置

Google Cloud Vision は **月 1,000 ユニットまで無料**（送った画像1枚が1ユニット。使う機能ごとに課金される。[公式料金](https://cloud.google.com/vision/pricing) で 2026-08-28 確認）。超過分の Document Text Detection（このツールが使っている文字読み取りの機能）は 1,000 ユニットあたり $1.50。帳票1ページ＝1ユニットなので、月 3,000 枚なら超過 2,000 ユニット＝約 $3。

**強制停止の安全装置**: 月 900 ユニット（`config.json` の `api_monthly_cap`）に達すると、送信を行わずに停止する。警告ではなく停止にしているのは、課金が後から取り消せないため。残量は GUI の実行画面に出る（コマンドラインでは `verify` でも確認できる）。

- カウンタの場所: `%LOCALAPPDATA%\ChouhyoOCR\api_usage.json`（`workdir` の外。`purge` しても消えず、複数の作業フォルダをまたいで合算される）。**この場所は設定で変えられない**——作業フォルダを分けても `config.json` を差し替えても、同じ Windows ユーザーなら同じファイルを数える
- カウンタのファイルが壊れていたときは、別名（`api_usage.broken.<日時>.json`）へ退避してログに残したうえで、0 から数え直して処理を続ける。壊れたファイル1つで月次の読み取りを止めるほうが困るという判断。ファイルを消せば同じく 0 に戻る——このカウンタが止めたいのは「気づかないうちに送りすぎる」ことで、利用者が自分で上限を外す操作までは防がない
- **テスト（`--replay`）はカウントしない**——保存済み応答の再生で API を叩かないため、テストで無料枠を消費しない
- 限界: 数えるのは「このツールがこの PC から送った回数」だけ。別の PC や別のツールからの利用は数えられない。**正確な利用実績は GCP の課金ダッシュボードで確認する**。このカウンタは請求額を確かめるためのものではなく、送りすぎを止めるための安全装置と考える

## 用語のかんたんな説明

| 用語 | 説明 |
|---|---|
| OCR | 画像の中の文字を読み取る技術 |
| Google Cloud Vision API | Google が提供するクラウドの画像認識サービス。このツールは文字の読み取りに使う |
| ユニット | Vision API の課金の単位。送った画像1枚が1ユニット（月 1,000 ユニットまで無料） |
| 〓 | 自信を持って読めなかった箇所に置く記号。ここを紙の原本と見比べて直す |
| 中間データ（`workdir`） | 読み取り結果や展開した画像を溜めておく作業フォルダ。記入内容がそのまま入るので個人情報として扱う |
| `purge` | 中間データを消すコマンド |
| `--replay` | 保存してある過去の応答を使い回す動作。Google に送らないので料金がかからない |
| COUNTIF | Excel の関数で、条件に合うセルの数を数える。`"*〓*"` は「〓を含む」という書き方 |
| BOM 付き UTF-8 | 文字化けしにくい形式で保存しているという意味 |
| DPAPI | Windows に最初から入っている暗号化の仕組み。ログイン中の Windows アカウントに結びつけて暗号化するので、別のユーザーや別の PC からは元に戻せない |
| ACL / `icacls` | ACL はフォルダを誰が読み書きできるかの設定。`icacls` はそれを変える Windows のコマンド |
| IAM / サービスアカウント | どちらも Google Cloud 側の権限の話。サービスアカウントは、このツールが Google に自分を名乗るための「鍵」の持ち主 |
| SmartScreen | Windows が知らないアプリの起動時に出す警告画面 |
| Poppler | PDF を画像に変換するために同梱している外部ツール |
| dpi | 画像の細かさ。数字が大きいほど細かい |
| JSON | 設定やデータをテキストで書く形式。このツールでは鍵ファイルやテンプレートがこの形式 |
| コード署名 | アプリの開発元を証明する電子署名。付いていないと SmartScreen の警告が出る |
| 升（ます） | 表のセル。表の1行 × 1列のマス。Excel では1升が1列になる（`明細_03_備考` のように行番号と列名が付く） |
| キャンバス | テンプレート編集タブで、帳票の画像を表示して枠を描く作業スペース |
