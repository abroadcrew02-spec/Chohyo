**5.3 `template.schema.json` と暫定テンプレート JSON**

詳細設計書を書かないかわりに置く**検証可能な実体**。文章と違ってコードと乖離しない。

`template.schema.json` は 02_design.md §4.2 の構造を JSON Schema として形式化したもので、**Python コアと TypeScript エディタの契約**になる。要件 §8-14 が「エディタが書き出した JSON をコアがそのまま読めること」を求めており、両言語が構造を別々に解釈すればここが最初にズレる。コアは読み込み時、エディタは保存前に同じファイルで検証する。**スキーマの正本は1ファイル**とし、片方の言語の配布物に埋めない。

暫定テンプレート JSON は自作サンプル画像から手書きで作る。**テーブル定義スキーマ**（§3 参照）を採るため、手で決めるのは次の数値だけで済む。

- 表裏分割位置（Y座標1つ）
- 除外領域（綴じ穴帯の左右2つ＋黒塗り1つ）
- 表面の本人欄7項目の矩形（生年月日は元号・年・月・日の4分割）
- 家族欄のテーブル定義: 左右ブロックの原点2つ・行ピッチ1つ・列境界（続柄／氏名／元号／年／月／日）・行数5
- 明細のテーブル定義: 左右ブロックの原点2つ・行ピッチ1つ・列境界（年／月／日／金額／品目）・行数14（罫線の射影実測）

家族欄60列と明細140列は、この定義から格子として展開される。矩形を1個ずつ列挙すると欄は概算140個になるが、テーブル定義なら手で決める数値は20〜30個規模に収まる。

Q-12（無記入原本）が未入手のため座標は暫定。**実物入手時に差し替えるのはこの JSON 1ファイルだけで済む形にする**——これが「未入手のまま先行する」を成立させる唯一の条件になる。

このファイルは M6 の編集画面が完成するまでの間つなぎでもある。M1〜M5 はこの手書き JSON で動かし、M6 完成後にエディタが書き出した JSON へ差し替えて §8-14 を検証する。**エディタ待ちで M1 を止めない。**
