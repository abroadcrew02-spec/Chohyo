## 2. 背景・目的

出力列の構成はテンプレート定義から一意に導出される（`core/chouhyo_ocr/columns.py:29-34`。面の定義順 × 単発欄 → 表の順）。画面から変更する手段はない。

出力から欄を外す唯一の方法は**欄の削除**である（`gui/src/Editor.tsx:1662-1685`）。削除すると座標・項目種別・選択肢マークも同時に失われ、戻すには作り直しになる。

**実需の仮説**（R-Should）: 「この納品では出さないが、定義は残しておきたい」欄が発生する。備考欄のように読み取りはできるが納品項目に含まれないもの、家族欄10行のうち実運用で常に空になる後半行、取り込み先システムが受け付けない列——いずれも**次回は出したくなる可能性がある**。削除で対応すると、次回そのテンプレートを作り直すことになる。※この仮説はユーザーヒアリングによる裏付けを取っていない（要求の発生源は直接指示）。第1弾の運用後に実際どの欄が外されたかを記録し、仮説を検証する。

本機能の目的は、**テンプレートの座標定義を壊さずに出力列の構成（出力有無・順序）を変更できるようにすること**。

| | 第1弾: 欄単位の出力対象外 | 第2弾: 列の並べ替え |

### 3.5 実データ着弾に伴う再検証リスク（R-M1）

本機能が**技術的に**実データ待ち（Q-03/Q-12/Q-16）と無依存であるのは、次の3点の範囲に限られる。

- geometry_hash を変えない（F-6）ため、位置合わせ結果を無効化しない
- API 送信枚数・課金を増やさない（F-9）
- 中間データを無効化しない（テンプレート変更は remap 要求どまり・F-8）

**要件レベルでは無依存ではない。** Q-03/Q-12 の実データ着弾でテンプレート座標が作り直された場合、第2弾の並べ替え UI は前提が変わる——欄・表の粒度、220列という規模、**表の内部列の並べ替えが 220列中 200列を動かす**という構成（K-M1）は、いずれも現行の自作サンプル由来のテンプレートに基づく。行数や表の構成が変われば、上下ボタンの操作単位・列位置表示の表記・出力列リストの見せ方を再検証する必要がある。

**このリスクは第2弾に限定される。** 第1弾は列の有無だけを扱うため、座標が作り直されても仕様は変わらない。U-3 の2弾構成は、この非対称性をそのまま順序にしたものである。

### 3.6 「一度きり運用」との緊張（R-Should）

正本 §3.5 は「一度きり運用は v1 の対象範囲」と規定している。一度きりなら、列を出し分ける機能も、次回のために定義を残す動機も、本来は弱い。

この緊張は解消しないまま受容する。理由は2つ。第1弾は §8-16 として**すでに v1 の合格条件になっている**ため、一度きり運用の是非とは独立に返済が要る。第2弾は Q-26 でユーザーが前倒しを判断した——判断の主体はユーザーであり、本書はその判断を記録する立場にある。ただし §9 の「継続運用は第2段階で扱う」という区分は変更しない。**本機能は継続運用そのものを v1 へ持ち込むものではない**（差分更新・名寄せ・複数様式は引き続き第2段階）。

### 3.7 適用範囲外

列構成の圧縮（D-14 として別管理）／様式メタ情報（§9 候補1②）／複数様式の自動判別（§9 候補3）／出力ファイルごとの列構成差（Q-28 で共通に確定）

## 4. 機能要件

ID は 3層構成。**FR-0.x = 両弾の共通基盤／FR-1.x = 第1弾（出力対象外）／FR-2.x = 第2弾（並べ替え）**。

### 4.1 共通基盤

#### FR-0.1 出力列構成の唯一の正を verify 応答に置く 【Must】（B-M4）

- `verify` の応答に **`column_names`（順序付きの列名一覧）** を追加する
- FR-1.6・FR-2.6 の列構成比較、FR-2.3 の列位置表示、FR-2.7 の列名一覧は、**すべてこの応答を唯一の入力とする**。GUI 側で列名・列順を再導出しない
- 根拠: F-10 のバグは「同じ数を GUI とコアが別々に数えた」ことで起きた。列順という順序を持つ情報で同じ轍を踏むと、乖離が単なる数のズレではなく列の入れ替わりとして出力へ抜ける
- 付随: `render_out` の管理列数ハードコード `6` を `len(META_COLUMNS)` へ置き換える（B-Should）

#### FR-0.2 保存時差分表示の母集団を是正する 【Must】（F-10）

- 読み込み時と保存時で比較の母集団を揃える。無編集の保存で差分が出ない状態にする
- **この修正だけを先に単独でリリースし、無編集保存で差分ゼロになる実績を1回作ってから**、列に関する比較（FR-1.6）を足す（K-Should・P4-4）
- 根拠: 現状は無編集でも「欄 14→194（+180）」と出るため、差分表示そのものが信用されていない。信用のない表示器に列の警告を足しても読まれない

### 4.2 第1弾: 欄単位の出力対象外

#### FR-1.1 出力対象フラグ `output` 【Must】

- 欄（単発欄 `field`・表の列 `tableColumn`）単位で、出力列に出すかどうかを指定できる
- **属性名は `output`**（boolean・省略時 true・**false のときだけ JSON に書く**）。`enabled` は契約に対して虚偽（欄は何も disable されない——読み取りは走る）、`exclude` は除外領域（Vision マスク）と語彙が衝突するため採らない（B-確定）
- `output: false` の欄は xlsx / csv のどちらにも列として現れない（Q-28: 共通）
- 枠・座標・項目種別・選択肢マーク・正規化属性は維持される（削除との違い）
- 読み取りは維持し、値・信頼度・char_confs・origin は従来どおり中間データへ保持する（Q-29）
- **subfields を持つ欄を対象外にした場合、その欄由来のサブ列がすべて消える**（部分的に残さない・T-Should）
- **表の列を対象外にした場合は全行一括**（家族欄10行・明細28行のうち一部の行だけ外すことはできない）。`kind: choice` の列を対象外にしても `era.score_cell` は従来どおり走る（B-Should）
- 実装上、対象外判定は **`output_cells(template)` 1関数に集約**し、`derive_columns` / `build_row` / `build_failure_row` の3経路がすべてこの関数を通る（B-Should。列を作る側と値を作る側で判定がズレると列と値の対応が壊れる）

#### FR-1.2 対象外欄が母集団に残る範囲 【Must】（T-M8・B-Should・P3-a）

対象外の欄は「出力列でなくなる」だけであり、次のいずれの母集団にも**残る**。

| 母集団 | 扱い | 理由 |
|---|---|---|
| 空行判定（§5.5） | 残す | 対象外欄にのみ記入がある行を空行と誤判定すると、その行の他の欄が〓ではなく空文字になり、未記入と区別できなくなる |
| 欄の重なり検証 | 残す | 枠は残っているため。既存の W-1 3件の件数固定テストが変化してはならない |
| W-3 隣接死角警告 | 残す。ただし警告文に「（出力対象外）」の印を付ける（B-Should）。実装では W-1/W-2 にも同じ印を適用した（同趣旨・段2 実装時に拡張。判定は片側の欄が対象外なら付す OR 条件——出力に残る側の実害を「対象外だから無視」と誤読させないため） | 既存 W-3 12件の件数固定テストが変化してはならない。一方で「この警告は出力に出ない欄のものだ」と読み手が判断できる必要がある |
| field_id の一意性検証 | 残す | 対象外を解除した瞬間に列名が衝突する状態を作らないため |
| `fallback_rect`（参照の受け皿） | 残す。**対象外欄が `fallback_rect` を持つ場合、その参照先は受け皿として機能し続け、W-2 は従来どおり発火する**（B-S1） | 現行スキーマに「参照される欄」という属性は存在せず、`fallback_rect` は座標を指すだけであるため、`output` は参照関係に影響しない |
| **resolveOverlaps（保存時自動切り抜き）** | **残す。主張元にも被切り抜き側にもなる（P3-a）** | 外すと矩形が動いて座標不変ガードと可逆性を壊すうえ、重なりを誰も解消しなくなり `load_template` の重なり拒否でテンプレート自体が読めなくなる |
| `Row.origins` | values と同時にスキップする（B-Should）。**`debug_images._field_origins` と `assign()` の両方に `output` 対応を入れる**（F-13） | 値だけ落として由来色を残すと、debug-images で由来色が静かに死ぬ。由来算出が2経路あるため、片方だけの対応では `test_debug_images.py:249` が固定している一致が崩れる |

#### FR-1.3 抽出対象列が0になるテンプレートの拒否 【Must】（B-M3・T-M10）

#### FR-1.4 対象外欄由来の警告の可視化 【Must】（B-M2）

#### FR-1.5 対象外欄の画面表現 【Must】（K-M2・P3-b）

#### FR-1.6 保存時の列数ガード 【Must】（Q-30・K-M3）

### 4.3 第2弾: 列の並べ替え

#### FR-2.1 並べ替えの範囲 【Must】（K-M1・Q-27）

**実効的に並べ替えができるのは次の3つの閉区間のみ**であり、これを要件として明記する。

1. **面内の欄どうし**（`faces[].fields` の配列順）
2. **面内の表どうし**（`faces[].tables` の配列順）
3. **表の内部列どうし**（`tables[].columns` の配列順）

- **表を欄の間へ差し込むことは構造的に不可能**（列導出が「単発欄をすべて出してから表」の順であるため・F-1）。UI もこの操作を提示しない
- **面をまたぐ移動は不可**（`faces[]` の並べ替えは FR-2.2 で禁止）
- **③表の内部列の並べ替えが、220列中 200列を動かす本体である**（家族欄 60列＋明細 140列）。①②は 14列規模にしか効かない。第2弾の価値は③にある
- 管理6列は先頭固定・並べ替え対象外
- 列順の表現は配列順そのもの（スキーマ変更なし・U-2）

#### FR-2.2 順序契約の安全化 【Must】（U-2・B-M1）

- **座標不変ガード**: 並べ替えを含む保存では、resolveOverlaps の前後で全欄の矩形が 1px も変わらないことを検証する。変化した場合は保存を中止し、理由を表示する（重なりが残っているテンプレートでは、先に重なりを解消してから並べ替える運用）
- 根拠: 配列順は出力列順と切り抜きの主張優先順を兼ねる（F-12）。並べ替えは後者を黙って変える
- **`faces[]` の並べ替えを禁止する**——geometry_hash が変わり（F-6）、全ページが再課金対象になる
- **`blocks[]` の並べ替えを禁止する**——行番号の通番がズレて field_id が変わる（実質的な列の改名）
- 上記2つを NFR-03 の但し書きとして明文化する。`tables[]` どうし・`columns[]` どうしの並べ替えは安全（ぼたん検証済み）

#### FR-2.3 列位置表示（§5.10⑦ の縮退解除） 【Must】

- 選択中の矩形が出力の何列目に出るかを表示する。単発欄は「左から9列目 / 全220列」、表は範囲表記
- **canvas のラベルには出さない**（K-UI確定案）
- 表示の元データは verify の `column_names`（FR-0.1）。GUI 側で再導出しない（T-M11）

#### FR-2.4 出力列リストと canvas の相互ハイライト 【Must】（K-M5）

- 出力列リストの行を選ぶと canvas の対応枠が、canvas の枠を選ぶとリストの行がハイライトされる（既存 `hlCol` の拡張）
- 根拠: 220列規模では列番号の数字だけで対象を同定できない。並べ替え UI の前提実装として第2弾に含める

#### FR-2.5 履歴（Undo）への統合 【Must】（K-M4）

- 並べ替えと出力フラグは `fields` / `tables` 配列自身に載せ、既存の Snap（Undo）に自動で乗せる。**別 state を作らない**
- 1クリック＝1履歴コマ（明示 push）。Ctrl+Z で1手ずつ戻る

#### FR-2.6 保存時の列順変化の報告 【Must】（K-M3）

- 列順が変化した保存では**確認ダイアログを出さず**、保存後の msg / warnbox に変化内容を報告する
- 根拠: 並べ替えは意図した操作であり、毎回確認を出すと確認そのものが読み飛ばされる。列の**減少**（FR-1.6）とは扱いを分ける

#### FR-2.7 列名一覧スナップショットの出力 【Could】

### 4.5 第3弾: 升単位の出力対象外（2026-09-04 追加）

> ⚠️ **v1.0 からの変更点**: FR-1.1 は「表の列を対象外にした場合は全行一括（家族欄10行・明細28行のうち一部の行だけ外すことはできない）」と定めていた。本節はこの制限だけを解く。**欄・列の粒度（FR-1.1）は一切変えない**——升の指定は列指定の下に足す3つ目の粒度であり、既存テンプレートの読み方も、`output` 属性の意味も変わらない。

#### FR-3.1 升単位の出力対象フラグ 【Must】

- 表の1升（1行 × 1列）を単位に、出力列へ出すかどうかを指定できる
- **場所と形は `tables[].output_disabled_cells`**（配列・省略＝全升出力）。要素は `{"row_no": 整数, "column": 列名}` で、`row_no` はブロックを跨いだ 1 起点の通し番号（`field_id` の連番部分と同じ数え方）
- **列は名前で指す**（`columns[].name`）。添字にしない——第2弾の並べ替え（FR-2.1）で表の内部列の順序が動くため、添字だと並べ替えが指す升を黙って変える
- **極性は「外す升だけを列挙する」**。`output: false` を列挙する形と揃え、既定（何も書かない）が「全部出す」になる。列挙されなかった升に属性を書かない点も `output` と同じ（B-S4: 無関係な保存で `template_hash` を動かさないため）
- **列が優先**: `columns[].output: false` の列は、例外リストに何が書かれていても全行が対象外になる（`CellSpec.output` は「列の可否 AND 升の例外」の論理積）
- 実装上、対象外判定は**読み込み時に `CellSpec.output` へ畳み**、窓口は従来どおり `output_cells(template)` 1関数のまま（FR-1.1 の末項をそのまま継承する）。列を作る側・値を作る側・件数を数える側は粒度を区別しない

#### FR-3.2 実在しない升・重複の拒否 【Must】

- `row_no` がその表の総行数（`blocks[].rows` の合計）を超える、`column` が `columns[].name` に無い、同じ `{row_no, column}` が2つ以上ある——いずれも `load_template` が `TemplateError` で拒否する
- エラーメッセージには **`table_id`・`row_no`・`column`** を含める（どの表のどの指定かを、テンプレートを開かずに特定できるようにする）
- 根拠: 例外リストは「出力を減らす」指定なので、実在しない升を黙って無視しても出力が増えるだけで壊れた xlsx にはならない＝**実行時には何の症状も出ない**。行を減らした・列名を変えた編集の後で「外したはずの升が戻っている」ことに誰も気づけない
- **列が `output: false` でも検査は飛ばさない**。飛ばすと、列を出力対象へ戻した瞬間に壊れた指定が生き返る

#### FR-3.3 母集団・可逆性・ハッシュの扱い 【Must】

- FR-1.2 の母集団表（空行判定・重なり検証・W-1〜W-3・`field_id` の一意性・`fallback_rect`・resolveOverlaps・`Row.origins`）を**そのまま升へ適用**する。升を外しても物理セルは消えない
- 読取値は中間データに残る（Q-29 の可逆性）。抽出対象列が0になれば FR-1.3 の拒否に乗る
- `geometry_hash` は不変・`template_hash` は変化する（NFR-01）。したがって `check_reusable` は run ではなく **remap** を要求する

#### FR-3.4 画面表現 【Must（2026-09-04 実装）】

> v1.1 では本項を **Won't（core と JSON 直接編集まで）** としていた。GUI 側が同じ 2026-09-04 に入って出荷されたため、v1.2 で Must へ移す。内訳の要件は FR-3.5〜FR-3.8、受入基準は §7.5.1。

- テンプレート編集画面から升を選んで外せる。キャンバスで表を選んでから升を選ぶと、右パネルの「選択中の升」で「出力する」を切り替えられる（列一括ボタン付き）。JSON 直接編集（§3.5 の CLI 等価）でも同じ構成を作れる
- 出力しない升は斜線ハッチ、⊘ は縦に連続する出力しない升のまとまりに 1 個（画面上 24px 以上のときだけ）。出力列タブは表を行 × 列のグリッドで並べ、列見出しで列ごと一括に切り替えられる
- 保存は編集中の升の指定を `output_disabled_cells` へ書き出す（規則は FR-3.6）。件数の数え方と母集団の表示は FR-3.8、破壊的な編集への追従は FR-3.5、画面上の表現と選択操作は FR-3.7
- 出荷単位: core（schema・`_expand_table`）と GUI（編集・保存）を同じリリースに含める。片方だけだと、手書きした升指定を編集画面で開いて保存した時点で失う経路が残る（2026-09-04 に両方が揃った時点で解消）

#### FR-3.5 破壊的な編集への追従 【Must（2026-09-04 実装）】

- 列名の変更・列の削除・ブロックの行数変更／増減で、升の指定を張り替える。列名の変更は旧名のキーを新名へ移し、列の削除はその列のキーを落とす
- 行数の変更・ブロックの増減では、升の指定を **（ブロック番号, ブロック内の行番号）** を基準に写す。通し行番号で写すと、先頭ブロックの行数を変えただけで後続ブロックの指定が 1 行ずつずれる
- 範囲外へ出た指定は取り消し、その件数を保存前の確認に 1 行出す（「行の外に出た『出力しない升』の指定 N 件を取り消しました」）
- 追従は元の編集と**同じ差し替え**で行う。2 回に分けると Undo が 2 コマになり、行数を戻すだけでは升の指定が戻らない

#### FR-3.6 列と升の実効状態・保存規則 【Must（2026-09-04 実装）】

- 列チェックの表示（レ点／空／中間）と押したときの向きは 1 つの関数が決める。三値は「すべて出力する」「すべて出力しない」「一部だけ出力しない」で、列ごと出力しない列は無条件に「すべて出力しない」
- 一括切り替えの遷移: すべて出力する・一部だけ出力しない → **列ごと出力しない**（升の指定は触らない）／列ごと出力しない → **列を戻す**（升の指定は触らない＝戻すとまた効く）／全升を 1 つずつ外した状態 → **列を戻す＋その列の升の指定を全消去**（戻す先の「列ごと出力しない」が無く、消さないと押しても何も変わらないため）
- 中間状態から押したときは必ず「外す」方向へ倒す。押すたびに向きが変わると、一括操作の結果を予測できない
- 保存規則は 4 つ。①有効な指定が 0 件なら `output_disabled_cells` のキーごと省略する（空配列を書くと升を触っていない保存で `template_hash` が動く） ②列ごと出力しない列の升の指定は書かない（列が優先・FR-3.1） ③実在しない行番号・列名は書かない（`load_template` の拒否に頼らず画面側で刈る） ④`row_no` 昇順 → 列の定義順に並べる（同じ編集内容なら同じバイト列になる）
- 読み込みは逆変換で、実在しない行・列を落としてから state に入れる

#### FR-3.7 画面上の表現と選択操作 【Must（2026-09-04 実装）】

- キャンバスの升の選択は 2 段クリック。1 回目で表を選び、2 回目で升を選ぶ（既存の「表を選ぶ」操作を壊さないため）。行の隙間・列の隙間をクリックしたときは升を選ばず、表の選択に落とす
- ⊘ は縦に連続する出力しない升のまとまりに 1 個。ブロックを跨ぐ連なりは分割する——通し行番号は連続でも、紙の上では離れた場所に飛ぶため
- 出力列タブでは表を行 × 列のグリッドで並べる。開くのは一度に 1 つの表だけ（全表を同時に描くと DOM が升の数だけ膨らむ）。総行数が 100 を超える表は途中まで描き、「もっと見る（残り N 行）」で伸ばす
- 升チェックの読み上げ名には表名・行・列と現在の状態を含める（「明細 3行目 備考を出力する（現在: 47列目）」）。表名を落とすと、表が複数ある紙で同じ名前が並ぶ
- グリッドの直下 1 行に、ふれている升の列番号を出す。並べ替えた直後は列番号を出さず「保存すると列番号が確定します」に差し替える（確定前の番号を出さない・FR-0.1）
- 升・列のチェックボックスにフォーカスがある状態でも Ctrl+Z／Ctrl+Y は効かせる。升を 1 つ外した直後はそのチェックにフォーカスが残るため、一律に「入力中」として止めると取り消しが効かない。Delete・矢印は従来どおり止める
- 升・列の切り替えは押した時点で履歴を 1 コマ積む（静止時間を待つ経路に頼らない）

#### FR-3.8 母集団・件数の表示 【Must（2026-09-04 実装）】

- 対象外の件数は**物理升**で数える。列ごと外した分はその表の総行数、升ごと外した分はその件数。verify の `output_disabled_cells` と単位を揃える
- 列ごと出力しない列に残っている升の指定は二重に数えない（保存でも書かないため、verify の値とずれる）
- 保存**前**の確認は管理 6 列を含む列数で出す（「出力列が 220 → 205 列に減ります。」）。保存**後**のサマリは要確認セル数が数える範囲＝抽出列数で出す（「要確認セル数の母集団: 214列 → 199列（出力しない 欄 2・升 13）」）。2 つは数える範囲が違うので、同じ数字にはならない
- サマリは列数と内訳を「を除く」で結ばない。列数は verify の実測、内訳は画面側の集計で、subfields を持つ列の升は 1 升 = N 列に展開されるため差と合計は一致しないことがある（AC-3.33）
- 抽出列数が減っていない場合、または対象外が 0 件の場合は母集団の注記を出さない。欄と升は別に数えて別に書き、0 のほうの項は落とす

## 6. 入出力・永続化仕様

### 6.1 スキーマ変更（`schema/template.schema.json`）

| 追加項目 | 位置 | 型 | 既定 | 影響 |
|---|---|---|---|---|
| `output` | `$defs/field` と `$defs/tableColumn` | boolean | true（省略時は出力する。false のときだけ書く） | geometry_hash 対象外（F-6）／template_hash は変わる＝remap 要求（F-7・F-8） |
| 列順の表現 | `faces[].fields` / `faces[].tables` / `tables[].columns` の**配列順そのもの** | — | 定義順 | **スキーマ変更なし**（U-2） |
| `output_disabled_cells`（第3弾・2026-09-04） | `$defs/table` | 配列（要素 `{row_no: integer 1..1600, column: string}`・`additionalProperties: false`） | 省略・空配列＝全升出力 | `output` と同じ（geometry_hash 対象外／template_hash は変わる）。`row_no` の上限 1600 は `blocks` の maxItems 8 × `rows` の maximum 200 |

**`output_disabled_cells` の description（第3弾・確定）**:

> 升（1行 × 1列）単位で出力列から外す例外リスト。省略・空配列＝この表の全升を出力する（既定）。列全体を外すのは `columns[].output: false` のままで、こちらは「この列のこの行だけ外す」ための追加指定。`columns[].output` が false の列はこのリストの有無に関わらず全行が対象外になる（列が優先）。false の升も読み取り・重なり検証・空行判定・field_id の一意性検証は従来どおり行い、読取値は中間データに保存される（再指定で API 再送信なしに復帰できる）。幾何セクションではないため geometry_hash は変わらず、template_hash は変わる（remap が必要）。maxItems は意図的に置かない——要素数の実質的な上限はその表の総升数（`blocks` の総行数 × `columns` の数）で、それを超える指定は重複または実在しない升として読み込み時に必ず落ちる。表の大きさから決まる値をスキーマへ定数で二重に持つと、表の上限を変えたときに片方だけが古くなる。

- `column` を**列名**にしたのは、第2弾の並べ替えで表の内部列の順序が動くため（添字だと並べ替えが指す升を黙って変える）
- `table_id` は既存の pattern `^[A-Za-z0-9._-]+$` により ASCII のみで、日本語の表 ID は作れない。列名（`columns[].name`）には pattern が無く日本語のまま置ける——`output_disabled_cells.column` も同じ制約に従う
- **`maxItems` は置かない**（上記 description の末尾に理由を明記）。数の上限はスキーマではなく FR-3.2 の実在性・重複検査が実質的に与える
- **`row_no.maximum: 1600` は `blocks.maxItems`（8）× `blocks[].rows.maximum`（200）と一致させる**。どちらかを緩めたときに上限だけが取り残されないよう、この一致そのものをテストで主張する（`test_h05_row_no_maximum_matches_the_grid_bound_it_stands_for`）

**`output` の description（確定・`$defs/field` と `$defs/tableColumn` の両方に同文）**:

> この欄を出力列に出すか。省略時は true。false でも読み取り・重なり検証・空行判定・field_id の一意性検証は従来どおり行い、読取値は中間データに保存される（再指定で API 再送信なしに復帰できる）。幾何セクションではないため geometry_hash は変わらず、template_hash は変わる（remap が必要）。

### 6.2 中間データ・出力

- 中間データ: 対象外欄の読取値・信頼度・char_confs・origin は従来どおり保持（Q-29）
- 出力: 列構成のみが変化する。xlsx の型指定・条件付き書式・COUNTIF 数式の規則（§5.6）は変更しない。**ただし列範囲に依存する4経路すべてが導出後の列数へ追従する必要がある**（T-M7）——①要確認セル数の COUNTIF 範囲 ②xlsx 条件付き書式2本 ③csv の静的カウント ④`unclear_char_level` の ON/OFF 分岐
